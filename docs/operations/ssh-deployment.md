# SSH Deployment Runbook

This runbook is the current durable source of truth for Lorume production and real-device deployment. The current release process is manual SSH operation: there is no repository-owned CI workflow or one-command remote deploy script yet.

Keep secrets out of this file. Known SSH aliases, usernames, hostnames, and IP addresses may be documented so the runbook is executable. Do not commit private keys, device tokens, session cookies, bearer tokens, database credentials, or raw production logs.

## Scope

- Production server deployment updates the verified Lorume production host `root@lorume.com`.
- Production runtime shape follows [../product/backend-service-spec.md](../product/backend-service-spec.md): Nginx terminates HTTP/TLS/WebSocket, Docker Compose runs Postgres/backend/frontend, backend and frontend bind only to loopback or internal compose networking, and Postgres is not publicly exposed.
- Real-device deployment currently includes `gezilinll-claw`. The collector is installed or updated by SSHing into the device and running the one-line installer command generated by Organization Settings.
- Production smoke checks are read-only. They must not create device tokens, run installers, POST collector payloads, mutate database rows, or clean production data.

## Local Preconditions

Before server deployment:

```sh
npm run verify
git status --short
git push origin main
```

Before real-device collector deployment:

- Confirm the production server smoke path is healthy.
- Generate or reuse a valid device token from `/settings`.
- Use Device ID `gezilinll-claw` for the real device unless intentionally rotating to a new device identity.

## Local Environment

Known SSH targets:

| Purpose | Alias | User | Host / IP | Usage |
|---|---|---|---|---|
| Production server | `lorume.com` | `root` | `lorume.com` | `ssh root@lorume.com` |
| Real device | `gezilinll-claw` | `gezilinll-claw` | `10.1.67.61` | `ssh gezilinll-claw` |

Use local shell variables for repeatable commands:

```sh
export LORUME_PROD_SSH="root@lorume.com"
export LORUME_PROD_ROOT="/opt/lorume"
export LORUME_CLAW_SSH="gezilinll-claw"
```

Before deploying, verify the production host and current release:

```sh
ssh "$LORUME_PROD_SSH" 'hostname; readlink -f /opt/lorume/current'
```

## Production Server Deploy

Deploy current `main` as a new immutable release directory over SSH:

```sh
git push origin main

release_id="$(date +%Y%m%d%H%M)-$(git rev-parse --short HEAD)"
release_dir="$LORUME_PROD_ROOT/releases/$release_id"

ssh "$LORUME_PROD_SSH" "mkdir -p '$release_dir'"
rsync -az --delete \
  --exclude '.git' \
  --exclude 'node_modules' \
  --exclude 'dist' \
  --exclude 'playwright-report' \
  --exclude 'test-results' \
  ./ "$LORUME_PROD_SSH:$release_dir/"
```

Build and switch the active release on the production server:

```sh
ssh "$LORUME_PROD_SSH" "
  set -euo pipefail
  cp '$LORUME_PROD_ROOT/current/.env' '$release_dir/.env'
  cd '$release_dir'
  npm ci
  npm run check:deploy
  docker compose -f docker-compose.prod-like.yml up -d --build
  docker compose -f docker-compose.prod-like.yml ps
  ln -sfn '$release_dir' '$LORUME_PROD_ROOT/current'
"
```

Then run public production smoke from the local machine:

```sh
npm run smoke:production
```

Run authenticated read-only smoke only when a valid operator-local session is available:

```sh
LORUME_DEVICE_ID=gezilinll-claw LORUME_SMOKE_COOKIE="<session cookie>" npm run smoke:production
```

or:

```sh
LORUME_DEVICE_ID=gezilinll-claw LORUME_SMOKE_BEARER_TOKEN="<bearer token>" npm run smoke:production
```

The authenticated smoke checks Runtime Fleet, Runs, collection-health, and diagnostics read paths. It must remain read-only.

## Production Server Inspection

Check service state:

```sh
ssh "$LORUME_PROD_SSH" "
  cd '$LORUME_PROD_ROOT/current'
  docker compose -f docker-compose.prod-like.yml ps
"
```

Inspect recent logs:

```sh
ssh "$LORUME_PROD_SSH" "
  cd '$LORUME_PROD_ROOT/current'
  docker compose -f docker-compose.prod-like.yml logs --tail=120 backend
"
```

```sh
ssh "$LORUME_PROD_SSH" "
  cd '$LORUME_PROD_ROOT/current'
  docker compose -f docker-compose.prod-like.yml logs --tail=120 frontend
"
```

If Nginx config is edited on the host, validate before reload:

```sh
ssh "$LORUME_PROD_SSH" 'sudo nginx -t && sudo systemctl reload nginx'
```

## Production Rollback

Rollback is also SSH-based. Reset the remote checkout to a known good commit, rebuild, and smoke again:

```sh
ssh "$LORUME_PROD_SSH" "
  set -euo pipefail
  ln -sfn '$LORUME_PROD_ROOT/releases/<known-good-release>' '$LORUME_PROD_ROOT/current'
  cd '$LORUME_PROD_ROOT/current'
  docker compose -f docker-compose.prod-like.yml up -d --build
"
npm run smoke:production
```

## Real Device Collector Install Or Update

The canonical install command is generated in Organization Settings. It has this shape:

```sh
curl -fsSL "https://lorume.com/api/device-collector/install.sh" | bash -s -- --server-url "https://lorume.com" --device-id "gezilinll-claw" --device-token "<device token>"
```

The current `gezilinll-claw` installation uses `https://claw.gezilinll.com` as its configured server URL. Keep that URL when reinstalling from the existing device config unless intentionally rotating the device endpoint; this device has not been reliable when fetching `https://lorume.com` directly.

Run it on the real device through SSH:

```sh
ssh "$LORUME_CLAW_SSH" '<paste the generated one-line installer command>'
```

Re-running the generated command is the supported update/reinstall path. It refreshes installed device package files, writes the current config, and reloads the launchd or systemd service. If rotating the device token, generate a fresh token first and rerun the generated command.

For a one-off foreground validation run after install:

```sh
ssh "$LORUME_CLAW_SSH" '<paste the generated one-line installer command> --once'
```

## Real Device Collector Inspection

Confirm install files exist:

```sh
ssh "$LORUME_CLAW_SSH" 'test -f ~/.lorume/collector/config.json'
```

Read collector logs without copying secrets into docs or commits:

```sh
ssh "$LORUME_CLAW_SSH" 'tail -n 120 ~/.lorume/collector/collector.log || true'
```

```sh
ssh "$LORUME_CLAW_SSH" 'tail -n 120 ~/.lorume/collector/collector.err.log || true'
```

```sh
ssh "$LORUME_CLAW_SSH" 'tail -n 120 ~/.lorume/logs/collector.jsonl || true'
```

On macOS devices, inspect launchd:

```sh
ssh "$LORUME_CLAW_SSH" 'launchctl print "gui/$(id -u)/ai.lorume.collector" | head -80'
```

On Linux devices, inspect systemd:

```sh
ssh "$LORUME_CLAW_SSH" 'systemctl --user status lorume-collector.service --no-pager'
```

Then check production from the local machine:

```sh
LORUME_DEVICE_ID=gezilinll-claw npm run smoke:production
```

Use authenticated smoke when checking Runtime Fleet collection-health or diagnostics.

## Real Device Collector Stop Or Uninstall

Use the installed CLI package on the device:

```sh
ssh "$LORUME_CLAW_SSH" 'node ~/.lorume/collector/lorume.mjs collector stop --json'
```

```sh
ssh "$LORUME_CLAW_SSH" 'node ~/.lorume/collector/lorume.mjs collector uninstall --json'
```

Do not manually delete Lorume files, launchd plists, systemd units, logs, or task sync cache to hide uninstall defects. If uninstall leaves residue, fix the installer/CLI behavior and rerun the real-device verification.

## Safety Boundaries

- Do not run local E2E or backend integration harnesses against production; they are allowed to create tokens, install collectors, POST snapshots, and clean isolated databases.
- Do not paste tokens, cookies, bearer tokens, private keys, database credentials, or raw secret-bearing logs into docs, commits, screenshots, or final reports.
- Use the backend product model and API as the source of truth. Do not change backend semantics to match a frontend assumption.
- Public domain reachability is operational validation, not a required local harness condition.
